# 검색 소스 전반 개선 및 실제 요청 검증 — 2026-10-28

## 확인 방법

Aside의 실제 로그인 세션과 별도의 Chrome DevTools 백그라운드 컨텍스트에서 검색 화면, 상품 페이지, DOM 및 Network 요청을 조사했다. 사용자 브라우저의 쿠키나 Cloudflare 통과 상태를 운영 서버에 복사하지 않았다. 정상 브라우저 접근, 별도 브라우저 접근, 서버 HTTP 수집은 별도로 확인했다.

운영 API의 이전 버전과 검증 배포에 같은 10개 검색을 수행한다. `scripts/benchmark_live_sources.py`는 강제 새로 조회, 첫 결과 시간, 전체 완료 시간, 소스별 상태·실제 상품·저자·ISBN, HTTP 요청 수를 기록한다. 실제 사이트 소수 실측이며 통계적인 전체 정확도로 해석하지 않는다. 모의 회귀 테스트와 실검색 결과를 구분한다.

## 조사한 소스별 요청과 반영

## 공통 탐색·식별 흐름

1. 교보 공개 목록에서 제목·저자·ISBN을 우선 식별하고 미확인 시 알라딘 카탈로그로 보완한다. 한 API가 느리다고 국내 소스가 제각각 첫 결과를 고르지 않도록 한다. 식별을 끝내지 못하면 검증 없이 동명 도서 결과를 다시 합치지 않는다.
2. ISBN이 있는 국내 소스는 그 판본을 먼저 찾는다. 해당 판본이 없으면 알려진 저자를 유지한 채 제목 검색을 재시도한다. 사용자가 직접 입력한 ISBN은 다른 판본으로 완화하지 않는다.
3. 제목 검색은 작품 기준이므로 권수가 명시되지 않았을 때 여러 권으로 나뉜 판본을 찾을 수 있다. 권수를 입력하면 기존 권수 불일치 차단을 유지한다. 가능하면 첫 권을 우선한다.
4. `제목 저자`, `저자 제목` 입력에서 실제 후보의 저자 메타데이터로 확인한 단어만 분리한다. 임의 단어를 삭제해 유사한 책을 만들지 않는다.
5. 원어 저자명은 ISBN을 검증한 Yes24 판본의 ‘저’ 소개 영역에서 얻는다. 번역자나 관련 추천 작가의 영문 이름을 사용하지 않는다. 동명 저자를 막으면서 여러 언어의 표기를 연결한다.
6. Open Library의 Work → matching Edition → ISBN 연결과 author key의 대체 이름을 활용한다. 원제와 영문 제목이 다르더라도 같은 작품의 판본 연결이 확인되어야 사용한다. 작품·평점의 고정 검색어별 정답 분기는 두지 않았다. 관측한 일부 저자명 표기 차이는 명시적인 인명 별칭으로만 보관한다.

작품 검색의 해외 소스는 검증한 원제·저자로 제목 검색을 먼저 수행하고, 필요한 경우 ISBN으로 보완한다. 사용자 지정 ISBN은 ISBN을 먼저 조회한다. Open Library 작품 카탈로그를 기본 우선순위로 두고 다른 공급자를 보완 경로로 사용한다. 서점 상품의 ‘오디오 포함’ 같은 설명을 다른 소스의 필수 검색어로 전달하지 않는다. 교보에서는 식별 단계에서 이미 파싱한 상품·점수·수치를 재사용하므로 큰 목록 HTML을 다시 파싱하지 않는다.

TTB 원제 조회가 실패하면 검증한 ISBN을 통해 외부 카탈로그의 작품 연결을 보완한다. 작은 TTB API 응답의 대기 한도를 4초로 두어 원제 조회 전체 기한을 한 공급자가 소모하지 않도록 한다. 국내 스트리밍 결과는 원제 조회 완료를 기다리지 않는다.

Open Library는 `editions.key`를 포함해야 이번 조사에서 실제 matching edition 문서가 반환되었다. `fields`에 작품과 판본의 식별자·제목·ISBN을 함께 요청한다. [Search API](https://openlibrary.org/dev/docs/api/search), [Authors API](https://openlibrary.org/dev/docs/api/authors)의 구조를 실제 응답과 대조했다.

교보 후보는 제목 표기 점수를 바로 비교하지 않고 저자 ID별로 묶은 뒤, 검증한 서로 다른 ISBN의 관측 평가 수와 판본 수로 작품을 우선 선정한다. 완전히 같은 제목의 다른 저자가 ‘1권·2권’ 표기 때문에 원작보다 먼저 선택되는 문제를 막는다. 이 기본 선택은 카탈로그 신호를 쓰는 휴리스틱이며, 특정 저자가 필요하면 제목과 저자명을 함께 입력할 수 있다.

이전 식별 규칙과 검증 중간본의 검색·소스 캐시는 최종 버전 10에서 재사용하지 않는다. 과거 검색 기록은 남기고 기존처럼 재검증 안내를 표시한다.

## 실검색에서 드러난 기존 문제

- ‘인간의 굴레에서’는 모든 국내 소스에서 정상 분권 제목을 제외했고 해외 검색도 시작하지 못했다.
- ‘전쟁과 평화’는 Yes24·사락에서 아자 가트의 동명 도서를 골랐다.
- ‘죄와 벌’도 Yes24·사락에서 김동인 작품을 골랐고, 알라딘은 청소년 판본을 우선했다.
- `Clean Code`는 국내 일부 소스에서 Kameron Hussain의 다른 책을 골랐다.
- `1984`의 LibraryThing 검색은 그래픽노블 후보를 채택했다. 평점은 없었지만 작품 정보 자체도 잘못될 수 있었다.

이 사례들은 제목 몇 개에 대한 URL·평점을 고정하는 방식으로 수정하지 않았다.

추가 검증에서는 Goodreads가 AWS WAF 안내를 HTTP 202로 반환하는 경우도 확인했다. 이를 빈 검색으로 파싱하지 않고 차단으로 분류한다. 정상 HTML을 얻기 위한 브라우저 호환 HTTP 및 실제 Accept 헤더를 적용했다. 서버가 다시 제한하면 해당 상태를 유지한다. 평점 참여가 0인 판본의 숫자 0을 평균 별점으로 쓰지 않으며, 작품 검색에서는 다른 검증된 판본을 재탐색할 수 있다. 사용자 지정 ISBN은 그대로 보존한다.

Amazon의 오디오북 제외는 선택된 상품 형식에만 적용한다. ‘다른 형식: 오디오북’ 안내가 있다는 이유로 종이책까지 제외하지 않는다. 소스 진단에는 공개 검색어·상품 제목과 식별 실패 종류만 기록하고 인증 정보나 원문 응답 전체를 노출하지 않는다.

## 검증 및 배포 결과

LibraryThing의 일반 브라우저 세션은 열렸지만 깨끗한 별도 Chrome 컨텍스트와 서버 HTML 요청은 Cloudflare 검증 페이지를 받았다. 추가 조사에서 [공식 Work Info API 소개](https://blog.librarything.com/2008/03/first-cut-works-json-api/)의 공개 endpoint가 현재 서버 HTTP로 동작함을 확인해 별도 경로로 연결했다. 사용자 쿠키·CAPTCHA 통과 상태·프록시는 사용하지 않았다.

로컬 실제 응답에서 `9780192833983` → work 995, 8.51/10, 글 리뷰 520개, `9780451530172` → work 7701, 8.12/10, 글 리뷰 171개를 확인했다. API에는 별점 참여 수가 없으므로 null로 보존한다. 사이트 헤더는 5점 척도 두 자리, API는 10점 척도 두 자리라 변환 후 표시 정밀도가 다를 수 있다.

`9788937460111` 같은 한국어 분권 ISBN은 LibraryThing의 평가 없는 별도 work로 연결될 수 있다. 원서 ISBN도 작품의 일부를 담은 별도 묶음으로 연결되는 경우가 있었다. 작품 검색에서는 제목·저자를 검증한 Open Library의 동일 Work에 속한 ISBN을 최대 40개까지 한 번의 API 요청으로 조회하고, 그 안에서 LibraryThing의 소장 신호가 가장 큰 작품 묶음을 선택한다. 인접 검색 결과나 검증하지 않은 책의 ISBN은 섞지 않는다. 사용자가 직접 지정한 ISBN은 다른 ISBN으로 확장하지 않는다. 이 대표 작품 선택은 카탈로그 연결에 기반한 휴리스틱으로, 두 서비스의 작품 묶음이 항상 같음을 보장하지는 않는다.

LibraryThing 자체가 판본을 합친 작품 평점이므로 ISBN 검색 결과에도 ‘작품 전체 평가’를 명시한다. 응답의 제목·저자는 상위 ISBN 검증에서 확인한 메타데이터이며 API가 새로 제공한 필드로 간주하지 않는다. API가 work를 찾지 못했을 때 반환하는 false·빈 링크를 다른 책으로 채우지 않는다.

[API 이용 조건](https://www.librarything.com/developer/terms)에 맞춰 프로세스 내 요청 간격을 최소 1초로 제한하고 진행 중인 동일 요청 및 소스 캐시를 공유한다. 여러 Vercel 인스턴스 전체를 합친 전역 속도 제한은 아니다. 상업적 이용에는 별도 허락이 필요하다. Talpa·thingISBN·thingTitle은 작품 연결용이며, 현재 문서상 평점 수집 API와는 다르다.

Python 3.12에서 모의 회귀 테스트 241개가 통과했다. ISBN 불일치·잘못된 work 링크·점수 범위·0점의 평가 없음 처리·수치 종류·JSONP 비실행·요청 간격과 취소·분리된 작품 묶음 선택을 포함한다. 실제 수집 결과와 모의 검사 결과는 별도로 기록한다.

### LibraryThing API 반영 직전 실검색 비교

동시 검색 2개, 강제 재조회, 동일한 10개 입력으로 측정했다. 별점이 숫자로 확인된 소스 합계는 41 → 52, HTTP 요청 합계는 152 → 158, 첫 결과 중앙값은 0.838 → 1.142초, 전체 완료 중앙값은 10.833 → 13.992초였다. 이전의 동명 다른 저자·오디오북·각색본 결과도 41개에 포함되어 있으므로 숫자 증감을 정확도 지표로 해석하지 않는다. 더 많은 소스와 추가 식별로 전체 지연은 증가했다. 이 결과로 전체 속도 개선을 주장하지 않는다.

이 시점의 8개 작품 검색은 모두 국내 4곳과 왓챠 평점을 얻었고, Goodreads 7/8곳, Amazon 1/8곳을 얻었다. LibraryThing은 아직 HTML 경로가 차단되어 점수 없이 확인한 링크만 표시했다. 아래 최종 검증은 Work Info API 적용 후 별도로 측정한다.

실제 입력: 전쟁과 평화, 인간의 굴레에서, 데미안, 사피엔스, 어린 왕자, 죄와 벌, 1984, Clean Code, ISBN 9788937460111, 존재하지 않는 검색어 zxqv없는책987654.
