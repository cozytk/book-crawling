# Vercel 전환 및 검색 검증 — 2026-10-28

## 배포 구조와 검토 결론

호스팅과 영속 저장을 Vercel로 통합할 수 있어 실제로 전환했다. Next.js 웹 `book-crawling`, Python Functions API `book-crawling-api`, 비공개 Blob `book-crawling-history`를 사용한다. API와 웹 프록시의 실행 리전은 서울 `icn1`이다. GCP Cloud Run과 Supabase는 새 운영 요청 경로에 포함되지 않는다. 기존 자원을 삭제하거나 과거 원격 DB 기록을 이전하지 않았다. 도서 사이트·도서 정보 API 및 사용자가 선택한 AI 소개 공급자는 계속 외부 데이터 원천이다.

웹은 같은 출처의 `/api/*`만 호출한다. 서버 프록시가 별도의 Secret으로 API에 인증한다. 기존 웹 `ACCESS_TOKEN` 접근 제어를 유지한다. Blob은 비공개이며 파일 접근 자격 증명을 브라우저로 보내지 않는다. Vercel의 임시 파일시스템에 SQLite를 영속 DB처럼 두지 않는다. SQLite·Supabase 지원 코드는 로컬/이전 환경의 호환 경로로 남아 있다.

Blob에는 UUID별 불변 검색 기록, 최신순 인덱스, 검색어 캐시, 소스별 캐시를 분리한다. 기록 본문 저장이 성공한 뒤 독립 인덱스를 병렬 작성하므로 캐시가 아직 없는 본문을 가리키지 않는다. 공유 JSON 목록 전체를 덮어쓰지 않아 동시 검색이 서로의 기록을 지우지 않는다. 기록 화면의 범위는 최근 500개이며 읽을 책은 기존처럼 브라우저 저장소를 사용한다. 대규모 관계형 조회용 구조로 검증한 것은 아니다.

참고: [Vercel FastAPI](https://vercel.com/docs/frameworks/backend/fastapi), [Python runtime](https://vercel.com/docs/functions/runtimes/python), [Private Blob](https://vercel.com/docs/vercel-blob/private-storage), [Blob Python SDK](https://vercel.com/docs/vercel-blob/python-sdk-reference).

## 전달받은 검토 사항 반영

- **공통 식별**: 제목의 공백·구두점·부제·명시적인 출판 주석과 영한 병기를 정규화한다. 해설·워크북·요약·어린이판 등의 파생 도서, 명시한 숫자 권수 및 상·하권 불일치를 먼저 거른다. 임의 부분 문자열이나 느슨한 유사도로 다른 책을 채택하지 않는다. 알려진 저자가 있으면 상세 저자도 검사한다. 한국어/영어 저자명의 동등성을 자동으로 증명하지는 않는다.
- **알라딘**: 국내 검색과 원서 해석이 동일한 검색·상세 응답을 공유한다. 두 상세 경로의 요청 옵션을 일치시켰다. 판매량은 식별 검사를 통과한 후보 사이의 순위에만 반영한다. 별점 참여와 100자평 수를 분리한다.
- **교보**: 지정 ISBN은 상품의 식별자 속성으로 검사한다. 주변 임의 텍스트에 ISBN이 있다는 이유로 일치시키지 않는다. ISBN이 맞는 세트·에디션을 일괄 제외하지 않는다. 목록에서 점수를 얻은 경우 추가 대기와 통계 요청을 생략한다. 목록의 수치가 참여자 수인지 글 리뷰 수인지 확인되지 않으면 유형을 임의 지정하지 않는다.
- **Yes24·사락**: 공통 상품 식별을 통해 검증한 상품 번호와 메타데이터를 재사용한다. ISBN 검색은 상품 상세 Book 메타데이터의 ISBN과 상품 번호를 확인한다. 클릭 데이터는 검색어를 반복하므로 식별 근거로 사용하지 않는다. 상세 HTTP 응답은 평점 수집과 공유한다. 일반 `.yes_b` 숫자를 평점으로 쓰는 폴백을 제거한다. Yes24는 상품의 집계 평점 및 `data-review-count` 등 명시적 리뷰 영역만 읽고, 사락은 투표 참여 수를 따로 보존한다.
- **왓챠**: 연도·저자 표시를 제거한 제목으로 후보를 고른다. 상세에서 Book 종류와 해당 집계 평가를 확인할 수 있어야 수집한다. 영화 등 다른 종류의 집계나 페이지 전체의 임의 숫자를 쓰지 않는다.
- **Goodreads**: 요청 ISBN과 상세 ISBN을 확인하며 제목·알려진 저자도 재검증한다. Book JSON-LD 노드에만 집계 평가를 연결하고 5점 범위를 검사한다. 별점 참여와 글 리뷰 수를 분리한다. ISBN이 확인되지 않은 다른 판본을 사용자가 지정한 ISBN의 결과로 채택하지 않는다.
- **Amazon**: ISBN-13 중 978 계열은 대응 ISBN-10으로 변환해 `/dp/`에 접근한다. 979 계열은 검색에서 ASIN을 찾은 후 상세 ISBN을 검사한다. 일반 별점 요소와 개별 리뷰 점수 폴백을 제거하고 상품 집계 영역을 사용한다.
- **LibraryThing**: 불일치 후보를 강제로 고르는 폴백을 제거한다. 직접 제목 이동·검색·검색엔진 결과·상세 응답에 식별 검사를 적용한다. 임의 첫 소수 `(2.99)`를 읽지 않고 Book 집계 정보나 명시적 책 통계 영역을 사용한다. 검증되지 않은 값을 채워 넣지 않는다.

제목 검색은 작품을 비교하면서 선택된 사이트 판본과 원문 제목을 표시한다. ISBN 검색은 식별자가 일치한 상품으로 제한한다. ISBN이 같아도 각 사이트의 평점 집계가 다른 판본과 합쳐져 있을 수 있으므로 판본 전용 점수라고 보장하지 않는다.

`rating_count`와 `text_review_count`를 별도로 저장한다. 확인하지 못한 수치는 `null`이다. 기존 호환 필드 `review_count`는 관측한 대표 수치이며, 유형을 확인하지 못한 소스는 이를 참여자 수나 글 리뷰 수로 바꾸어 부르지 않는다. 합계에는 확인된 수치만 포함한다.

## 속도와 안정성

HTML 파서는 최대 16개 작업 스레드에서 실행한다. 서비스의 HTTP는 공용 비동기 클라이언트로 보내고 연결을 재사용한다. 같은 요청의 응답과 상품 식별을 공유하며, 프로세스의 같은 이벤트 루프에서 도메인별 동시 요청을 3개로 제한한다. 사용자 취소나 기한 초과 시 HTTP 대기와 진행 중인 네트워크 요청도 취소한다. 스레드에 시간 제한만 씌우는 방식으로 설명하지 않는다. 독립 실행용 기존 동기 어댑터는 유지한다.

같은 검색어·소스 집합·갱신 조건의 동시 요청은 진행 중인 수집 작업을 공유한다. 한 구독자의 종료가 다른 구독자의 검색을 취소하지 않으며, 마지막 구독자가 종료하면 수집을 정리한다.

플랫폼 조회 18초, 원서 해석 12초, 선택적인 AI 소개 20초의 상한을 둔다. 결과는 도착하는 즉시 스트리밍한다. 기존 무작위 대기 대신 서비스의 도메인 동시성 제한을 적용한다. AI 소개는 기본으로 실행하지 않으며 소개 실패 때문에 평점 검색을 실패시키지 않는다.

소스별 TTL: 정상 24시간, 일치 결과 없음/식별 불일치 10분, 차단 60초, 시간 초과/네트워크 오류 15초, 파싱 오류·일부 정보 누락 30초다. 전체 검색에서 한 사이트가 빠졌거나 점수·수치가 불완전하면 전체 24시간 캐시로 고정하지 않고 소스별 캐시를 적용한다. 강제 갱신은 둘 다 우회한다. 식별 규칙 버전 4 이전의 검색 캐시는 새 검색에 재사용하지 않는다. 이전 상세 기록에는 재검증 안내를 표시한다.

## 모의 응답·고정 정답 묶음 검증

Python 테스트 **202개**, 웹 SSE 경계 테스트 **2개**, TypeScript 검사, Next.js 프로덕션 빌드, `npm audit` 0건을 확인했다. 기존 테스트의 상품 식별 없는 성공 fixture와 일반 숫자 평점 fixture를 실제 검증 조건에 맞게 고쳤다. Goodreads의 성공 fixture는 Clean Code인데 다른 작품의 ISBN을 요청하던 테스트도 바로잡았다. 검증을 약화해 기존 기대값을 유지하지 않았다.

## UI 및 운영 검증 범위

따뜻한 종이색과 책갈피 모티프로 화면을 정리했다. 국내 4곳을 기본 선택하고 해외·전체·개별 선택을 제공한다. 이전 결과를 바로 재사용하고 새로 조회할 수 있다. 검색 진행·중단·시간 초과·수집 제한·일치 결과 없음·일부 정보 미확인을 구분하며 새 검색과 이전 검색의 응답이 뒤섞이지 않도록 취소 및 요청 식별을 처리한다. URL에는 검색어와 선택 소스를 함께 보존한다.

초기 화면 JavaScript는 114KB다. 선택적인 AI 소개의 Markdown 렌더러를 필요할 때 불러온다. 비교 카드에 원점수·환산 점수·확인한 평가 수 유형·판본 기준·ISBN·원문 링크를 표시한다. 검색 기록·상세·읽을 책도 모바일에서 줄바꿈하도록 정리했다.

Aside Chromium에서 데스크톱 UI와 실제 검색, 정렬, 읽을 책, 기록 조회를 확인했다. 402×681 CSS 픽셀의 동일 출처 iframe을 사용해 모바일 문서의 실제 미디어쿼리와 가로 넘침을 확인한다. Aside의 페이지 API에는 직접 viewport 크기 변경이 제공되지 않아 이 경로를 사용했다. 실제 iPhone Safari 기기 검증으로 표현하지 않는다.
